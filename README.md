# スマブラ レートランキング

身内向けのスマブラSPレーティングサイト。Next.js (App Router) + Supabase。

## 初回セットアップ

1. Supabase でプロジェクトを作成
2. SQL Editor で `supabase/migrations/` の 3 つを、**0001 → 0002 → 0003 の順に**、1つずつ丸ごと貼り付けて実行
3. Supabase の Authentication > Sign In / Providers で **「Allow new users to sign up」をオフ**
   （登録は合言葉つきの画面からだけ許可するため。オンのままだと合言葉を回避できます）
4. `.env.local.example` を `.env.local` にコピーして値を入れる
5. `npm install && npm run dev`
6. 管理者を作る（下記）

Vercel にデプロイするときは、`.env.local` と同じ4つの環境変数を Vercel に設定します。

## 管理者アカウントの作り方

管理者になれるのは、SQL（または Supabase の画面）で権限を付けたアカウントだけです。サイトの画面からは付けられません。

1. サイトの「はじめての人はこちら」から、管理者にしたい人が普通に登録する（ユーザー名は小文字で保存されます）
2. Supabase の SQL Editor で実行:
   ```sql
   update public.profiles set is_admin = true where username = 'ユーザー名';
   ```
   （Table Editor の `profiles` テーブルで、その行の `is_admin` にチェックを入れても同じです）
3. サイトを開き直すと、ヘッダーに「管理」が出ます
4. 権限を外すときは `is_admin = false` にします。管理者の一覧は `select username, is_admin from public.profiles where is_admin;`

### 管理者にできること

- **お知らせ**: 「お知らせ」ページで投稿・削除。最新3件がランキングページの上に出ます
  - 本文と、大会の「説明・ルール」は Markdown で書けます（見出し・箇条書き・太字・リンク・表・引用・コードなど）。見出しは大きくなりすぎないよう、本文サイズ前後に抑えて表示します。HTMLタグは無効です。表示の調整は `src/components/Markdown.tsx`
- **大会**: 「大会」ページで作成 → 参加者がエントリー → 大会ページで「エントリーを締め切ってトーナメント表を作る」
  - 表の作り方は「レートの高い順にシード」か「ランダム」。人数が2のべき乗でないときは、上位シードから順に不戦勝
  - 各試合は、参加者が「勝った / 負けた」を入力（一致で決着、食い違いは保留）。管理者はいつでも勝者を指定して決着できます（保留の裁定・不戦勝など）
  - 大会の試合はレートには反映されません
  - 「定期開催」は自動では繰り返さず、開催のたびに大会を作成します
- **対戦の裁定**: 「管理」ページで、入力が食い違った対戦の勝者を決める／放置された対戦を無効にする

## すでに 0001 を適用済みの環境をアップデートするとき

1. プロジェクトの `src/` と `supabase/` をこのzipの中身で置き換える（`.env.local` と `node_modules` はそのまま）
2. SQL Editor で `0002_battle_flow.sql` → `0003_announcements_tournaments.sql` の順に実行
   - 旧フローで途中だった試合は「無効」になります
   - 既存のメインキャラは「1戦目キャラ（先頭）」と「変更キャラ（残り）」に移ります
   - 過去の試合のスコア（2-0など）は保存されなくなります（勝敗とレート変動は残ります）
   - 「Could not find the function」と出る場合は `notify pgrst, 'reload schema';` を実行
3. 本番開始の直前に、`supabase/reset_test_data.sql` を1回だけ実行（テストのレート・履歴を初期化。アカウントとプロフィール設定は残る）

## 表示速度について

- ログインの確認は `getClaims()`（`src/lib/auth.ts`・`src/middleware.ts`）。Supabase の JWT 署名キーが「非対称キー」なら通信なしで確認できます。**Supabase の Project Settings > JWT Keys が従来の共有シークレットのままだと、この高速化は効きません**（動作は今まで通りで、遅くもなりません）。新しい署名キーへの移行をおすすめします
- Vercel の Functions Region は、Supabase のリージョンと同じ地域にしてください（例: Supabase が Tokyo なら Vercel は hnd1）。離れていると、1回の問い合わせごとに待ちが増えます
- ヘッダーとナビは `src/components/Header.tsx`、数字バッジは `src/components/Badges.tsx`。どちらも先に画面を出して、あとから埋まる作りです
- 対戦画面の自動更新は `GET /api/battle-signal`（`src/app/api/battle-signal/route.ts`）で状態を確認します

## アプリ化（PWA）

スマホのホーム画面やパソコンに「アプリ」として追加できます（ホーム画面から開くと、ブラウザのバーのない画面で起動します）。

- 画面の上にインストールの案内が出ます（`src/components/InstallPrompt.tsx`）。Android・パソコンの Chrome / Edge では「インストール」ボタン、iPhone では「ホーム画面に追加」の手順を表示します。すでにアプリとして開いているとき、「あとで」を押してから14日以内は出ません
- ブラウザ側の操作でも追加できます（Android の Chrome: メニュー > 「アプリをインストール」または「ホーム画面に追加」）
- 通知（プッシュ通知）はまだありません

### アプリ名・リンクプレビューの文を決めたら

- `src/lib/app-config.ts` を書き換えるだけです。正式な名前（`APP_NAME`）、ホーム画面のアイコンの下に出る短い名前（`APP_SHORT_NAME`、8文字前後まで）、説明文（`APP_DESCRIPTION`）、リンクを貼ったときの表示（`LINK_PREVIEW`）をまとめてあります
- 書き換えたら、バージョンを上げる必要はありません。すでにホーム画面に追加している人のアイコン名は自動では変わらないので、いったん削除して追加し直してもらってください
- ヘッダーに出るサイト名は `src/components/Header.tsx` にあります（こちらは別管理）

### アイコンを差し替えるとき

同じファイル名・同じサイズで画像を置き換えます。

| ファイル | サイズ | 用途 |
| --- | --- | --- |
| `public/icons/icon-192.png` / `icon-512.png` | 192×192 / 512×512 | 通常のアイコン（透明背景でも可） |
| `public/icons/icon-maskable-512.png` | 512×512 | Android が丸や角丸に切り抜く用。絵柄は中央の約6割に収め、背景は塗りつぶす |
| `src/app/apple-icon.png` | 180×180 | iPhone のホーム画面用。背景は塗りつぶす（透明だと黒くなる） |
| `src/app/icon.png` | 512×512 | ブラウザのタブのアイコン（ファビコン） |

リンクプレビューに画像を出したいときは、`src/app/opengraph-image.png`（1200×630 が目安）を置くと自動で使われます。

### 動作の確認

- `npm run dev` ではアプリ化の機能（Service Worker）は動きません。確認は `npm run build && npm run start` で行い、`http://localhost:3000` を開きます。スマホで確認するときは、https の Vercel 上で開きます
- Chrome の開発者ツール > Application > Manifest で、名前・アイコン・「インストール可能」の状態を確認できます
- `public/sw.js` はページやデータをキャッシュしません（ログイン状態や対戦の最新状態がずれるため）。通信できないときに画面を開いた場合だけ、`public/offline.html` を表示します

## バージョン表記の更新

- ヘッダーのサイト名の下に現在のバージョンが出ます。タップ（クリック）すると、最新バージョンのアップデート内容が開きます
- 更新するときは `src/lib/version.ts` の `RELEASES` の**先頭**に、新しい版（`version` / `date` / `items`）を追加するだけです。先頭が現在のバージョンになります（古い版は履歴として残ります）
- 表示にはこのファイルだけを使います（`package.json` の `version` は表示に使いません）

## 更新ルール（Claudeに更新を頼むとき）

### 作業の始め方

- 作業前に main の最新を取得し、`git log` で前回のバージョン更新以降のコミットを確認する
- 作者が自分で行った変更があれば、更新内容に含める

### バージョンの上げ方（`メジャー.マイナー.パッチ`）

- パッチ（1.0.1）: 不具合修正、文言、見た目の微調整
- マイナー（1.1.0）: 新機能や画面の追加
- メジャー（2.0.0）: 大きな仕様変更や、SQLの実行が必要になる大改修
- ユーザーの目に見える変更があるときだけ上げる（READMEのみ・内部整理のみの変更では上げない）
- 作者が自分で行う小さな編集では、上げなくてよい

### 更新内容の書き方

- バージョンは `src/lib/version.ts` の `RELEASES` の先頭に追加する。`date` は更新を作った日
- 友達が読む前提の平易な日本語で、1項目1行、3〜5件まで

### コミットメッセージ

- 毎回、出力の最後にコミットメッセージ案を付ける
- 形式は `feat: 〇〇を追加` や `fix: 〇〇を修正`。バージョンを上げるときは末尾に版を入れる（例: `feat: 大会の結果表示を追加（v1.1.0）`）

## 仕組み

- ログインなしで返すファイル: アイコン類は `src/middleware.ts` の `matcher` で除外している（通すとログイン画面へ飛ばされて表示されない）。PWA 用の `manifest.webmanifest`・`sw.js`・`icons/` なども除外済み。別の名前のファイルを足すときは、ここに追加する
- ログイン: ユーザー名 + パスワード（内部で `ユーザー名@smash.example.com` のメールに変換）。ログインのたびにルール画面を表示（確認の記憶は `rules_ok` Cookie に400日。ログイン・ログアウトで削除）
- 対戦: 相手を選ぶ → 相手もこちらを選ぶと成立（選択は30分で失効）。画面は数秒おきに自動更新
- 結果: 2本先取のマッチ全体で、双方が「勝った / 負けた」を入力 → 一致（片方が勝ち・片方が負け）で確定してレート反映。両方が勝ち、または両方が負けだと保留。保留中は何度でも入力し直せて、一致すれば確定。合意できないときは管理者が裁定
- 中止: 双方が「対戦を中止」を押すと中止（レートは動かない）
- レート: Elo（初期1500、K=32）。計算は DB 関数 `finalize_match` だけが行い、ブラウザからは書き換え不可
- 対戦画面: 対戦開始時点の拒否ステージ・キャラを保存して表示（途中でプロフィールを変えても影響しない）
- 編集する場所: ステージ・キャラ一覧は `src/lib/data/`、ルール文は `src/lib/rules.ts`
